# OmniScrape benchmarks

A reproducible harness that compares OmniScrape with other scraping and extraction tools. The README's
numbers come from here. The run it cites is committed in [`published/2026-11-27/`](published/2026-11-27/).

## What is measured

| Suite | Question | Tools in the published run |
|---|---|---|
| `parse` | CSS/XPath throughput and result correctness over 143 pages × 5 repeats | OmniScrape, Scrapling |
| `adaptive` | Does a broken selector still find the right element after a page changes? 1,377 mutated cases | OmniScrape, Scrapling |
| `extract` | Product and article field extraction F1 over 126 pages | OmniScrape, Trafilatura |
| `markdown` | Main-content Markdown F1 and boilerplate leakage over 66 pages | OmniScrape, Trafilatura |
| `render` | JavaScript-rendered pages per second, 60 pages | OmniScrape (shared and isolated contexts), Scrapling |
| `crawl` | Full crawl of a local 300-page site; coverage, duplicates and robots violations counted server-side | OmniScrape, Scrapling |
| `live` | Short crawls of `quotes.toscrape.com` and `books.toscrape.com` (needs internet) | OmniScrape, Scrapling |

The harness also has adapters for Crawl4AI, Scrapy, Crawlee, lxml, BeautifulSoup, selectolax, parsel,
markdownify and html2text (`adapters/`). They were **not** part of the published run, so no numbers for them
are claimed anywhere.

## How it stays honest

- Every (tool, suite) pair runs in its own subprocess; competitor tools are installed into separate virtual
  environments (`requirements/*.txt`) so versions never leak between tools.
- Ground truth for real pages comes from each site's own markup (JSON-LD, microdata, `<h1>`, ...), never from
  another tool's output.
- The adaptive mutation corpus is generated by this repository (`corpus/adaptive_cases.py`). It is a
  self-benchmark and says so wherever it is quoted.
- Memory is peak RSS of the worker process, sampled while the suite runs.

## Reproduce

```bash
pip install -e ".[dev,bench]"
python -m benchmarks corpus                       # regenerate the synthetic corpus and adaptive cases
python -m benchmarks envs                         # isolated per-tool environments (needs `uv`)
python -m benchmarks run                          # all 7 suites, writes results/<run>/ and report.html
python -m benchmarks run --suite parse,crawl --tools omniscrape,scrapling
python -m benchmarks run --quick                  # smaller corpus, fewer repeats
python -m benchmarks compare results/<old> results/<new>
```

`results/` and `corpus/data/adaptive/` are generated and git-ignored. To publish a run, copy its
`adaptive|crawl|extract|live|markdown|parse|render.json` and `meta.json` into `published/<date>/` and update
the README tables from those files.

## Layout

```text
benchmarks/
├── adapters/        one adapter per tool (common ToolAdapter interface)
├── corpus/          offline HTML corpus + ground truth (data/dev, data/holdout) and generators
├── requirements/    pinned per-tool environments
├── site/            local aiohttp test site (also used by the integration tests)
├── suites/          one module per suite
├── report/          HTML report builder
└── published/       committed results cited by the README
```

The corpus under `corpus/data/` is the large HTML/JSON set in this repository; it is test data, is marked
`linguist-vendored`, and is **not** shipped in the PyPI package.
